# S1.7 — Soundness audit of the REFUTED ownership verdicts

The S1.6 ownership dimension reported 201 `REFUTED` chains out of 370. `REFUTED` meant "the body is
complete and transfers nothing". That verdict rested on an assumption nobody had checked: that a
*complete* walk saw every object access. It did not — the walk silently refused accesses it could not
key (untracked bases, indices without provenance, indexed loads on untracked bases).

A refused access is exactly where a consumption can hide. Refuting ownership over it is a negative
claim without a counter-argument, which the phase rules forbid.

## The gate

`chains.ownership_summary_dimension` now requires `unresolved_accesses == 0` before it may return
`REFUTED`:

```python
unresolved = int(summary.get("unresolved_accesses") or 0)
if status == "complete" and unresolved:
    return dimension("ownership", UNKNOWN, "unresolved object accesses in a complete body", ...)
```

`UNKNOWN` is the fail-closed direction: the flow is not claimed, and it is not denied either.

## Measured effect

Over the 354 finding functions (per function, not per chain — the S1.6 chain count and this function
count are not interchangeable):

| Verdict | Count |
| --- | --- |
| `UNKNOWN` | 275 |
| `REFUTED` | **72** |
| `CONDITIONAL` | 7 |

**119 bodies** that the S1.6 rule would have refuted are now `UNKNOWN`, because their supposedly
complete walk had refused at least one object access. Their refusal reasons are dominated by
`load_untracked_base` (1'734), then `indexed_load_untracked_base` (94) and `index_without_provenance`
(82).

That is not a regression in coverage — it is the withdrawal of 119 negative claims that were never
supported. It also explains part of why S1.6 could report so many `REFUTED` chains while the same
kernel turned out to contain real ownership flows once the attribution improved.

## What the gate does not do

* It does not promote anything. No `UNKNOWN` became `CONDITIONAL` or `PROVEN` through this change.
* It does not touch the hop rungs. The 12 witnessed transfers and the 6 `REFUTED` control edges of
  S1.6 are recomputed unchanged (`SUPPORTED`).
* It does not weaken `REFUTED` for bodies that really are complete and access-free: those remain
  `REFUTED`, and the fixture `test_a_body_with_unresolved_object_accesses_cannot_refute_ownership`
  pins both directions.

## Open

The gate protects against false negatives but produces no new positives. Turning the 275 `UNKNOWN`
into real verdicts needs base provenance — the same blocker the release-site census names. That is
the next bounded hypothesis, not a licence to widen the search space.
