## W14B — authenticated admin shutdown (§15), wire catalogue revision R4 (offline)

* **One new operation, on purpose.** The frozen catalogue had no way to end an agent's lifetime:
  `session.shutdown` is the producer of the fourth exit reason. Core revision **R3**:
  `core/rpc/registry.py` gains `OperationSpec('session.shutdown', None, False, True)` — read-only,
  recovery-safe, and deliberately **capability-free**: capability-bearing operations are the
  privileged ones and are never wired on the target agent (the generator enforces that invariant, so
  the operation carries no capability and pins the admitted value `session.admin` in its wire
  contract instead). Interface schema, the machine-checked inventory table and the generated target
  catalogue follow (registry 35 → 36, target `wired` 16 → 17, argument rows 49 → 50).
* **Semantics.** The provider *requests* the end (it sets `rt->admin_shutdown`); the session loop
  acknowledges first and ends the session with BYE `ADMIN_SHUTDOWN`; the daemon turns that into exit
  reason `ADMIN_SHUTDOWN` (stop `EXIT_CONDITION`, process exit 0). No second exit path, no kernel
  state, no reboot, no loader, no persistence — pinned by the new `admin_shutdown` source gate.
* **Authentication and authorization.** Only an AEAD-authenticated session reaches the handler; the
  required `capability` argument must carry the one value the contract admits (`CAPABILITY_REQUIRED`
  otherwise) and the session must be live. The operation is served **only** by the resident agent:
  everywhere else the handler refuses with `OPERATION_DEFERRED`, so the single-session profiles keep
  exactly the served set they had. Recovery-safe by policy: a boot in recovery serves it.
* **An attempt without a session is refused, not fatal.** A wrong PSK, a truncated answer, a port
  scanner or a pre-handshake "shutdown" is counted (`sessions_failed`), changes no boot state, and
  the agent keeps serving — an unauthenticated peer must not have a kill switch. Frame-level
  corruption inside an authenticated session stays a fatal `PROTOCOL_CORRUPTION` exit.
* Tests: `tests/test_w14_daemon.py` 33 → 36 (accepted shutdown ends the lifetime cleanly;
  unauthenticated and unauthorised attempts refused; recovery-safe and resident-only), `test_06`
  restated to the new handshake-refusal semantics, `test_only_four_exit_reasons_have_a_producer`
  tightened (all four have one now).

## W14B — identity, session teardown, recovery semantics, dial-out backoff (offline)

* **§14 identity.** `HELLO` now carries the identity block: `build_id` (the identity the console
  build injects), `platform` (`ps4` / `host-standin`, a compile-time fact), `profile_id` (null when
  the build has no bound profile), `boot_id` (null on the agent side — W11 derives the digest on the
  host), `boot_sec`/`boot_usec` (null, never `0`, when unresolved), `boot_status` and
  `session_state`. Static fields are per agent lifetime, boot fields per boot, the nonce is fresh
  per session. `ps4rf_agent_identity` + `ps4rf_agent_identity_init()` make the split explicit;
  `--resident` passes the daemon's boot cache in. Host side: `session.py` exposes
  `IDENTITY_FIELDS`/`agent_identity`/`keys`, `resident.py::freshness_report()` checks the demands
  (same identity, own nonce/session id/transcript/key material, recovery raised but never lowered).
* **§2 isolation.** `ps4rf_res_teardown()` is the one session teardown: it hands the session's
  resource set back empty *before* the BYE reports the cleanup state, and refuses a set it cannot
  attribute to a session (nothing of the offending slot is touched). `agent_finish()` wipes the
  session key material, nonce prefixes and session id on every exit path — a source gate asserts that
  no other return exists after the keys do. Surviving state is boot/lifetime-scoped only.
* **§4/§5/§11 recovery.** `ps4rf_daemon_session_recovery_required()` is the single mapping from a
  finished session to a boot state: protocol obligation broken, undelivered answer to a mutating
  operation, work still in flight, leftovers, refused teardown. A plain EOF/RST is **not** in that
  list — a lost transport with a sound state now leaves the boot flag clear (it used to set it), and
  a leftover object is reaped instead of ending the agent (it used to exit). The router records
  `last_op_mutating` at the single dispatch point, the runtime seeds the boot-wide flag into every
  session, `session.status` reports `session_state`/`mutating_allowed`, and mutating work is refused
  *before* any provider entry. Only a new agent lifetime clears the flag.
* **§6 backoff.** Bounded exponential dial-out backoff: doubles from `--idle-pause-ms` to
  `--backoff-max-ms` (default 30 s) with a 50 ms floor that wins over a smaller cap. A missing
  controller changes no boot, recovery or capability state; the report records `dial_misses`,
  `dial_misses_total` and `dial_backoff_us`.
* Report additions: `cleanup_reaped`, `cleanup_refusals`, `cleanup_state`, `held_after_cleanup`,
  `undelivered_responses`, `undelivered_mutations`, `dial_misses_total`, `dial_backoff_us`,
  `recovery_source`, `recovery_transitions`.
* Tests: `tests/test_w14_daemon.py` 26 → 33 (identity freshness across two sessions, two-boot

## W14 — resident ps4rfd: life cycle, exit conditions, dial-out transport

* The resident daemon exists (`native/target/ps4rf_daemon.{h,c}`): one bootstrap per boot, then
  `BOOTSTRAP -> RESIDENT_IDLE -> SESSION_ACTIVE -> SESSION_CLEANUP -> RESIDENT_IDLE` per session. A
  normal `BYE` ends the session, never the agent. `ps4rf_daemon_accept()` is the single acceptance
  gate: `ACCEPT` only in `RESIDENT_IDLE` and only while no session is bound.
* Sessions run over the existing **dial-out** transport (`net_connect`, the host controller listens
  per session): no listener, no port and no health probe on the agent side. A missing controller is
  a recorded `dial_misses` and never fatal. A further connection while a session is active is
  refused on that connection with the unauthenticated `SESSION_BUSY` notice (§13, one per session);
  the notice carries no session id, no nonce and no key material and is validated strictly by the
  host.
* The agent exits only for the four reasons of §3: authenticated admin shutdown (**declared, no
  producer yet** — §15), fatal protocol corruption (handshake, unknown frame type, replayed session
  id), `RECOVERY_REQUIRED` with an unsafe agent state, and internal integrity failure (boot inputs
  not establishable, boot inputs changed since bootstrap, or a session that ended without
  `held resources = []` + cleanup `COMPLETE`). A lost transport and `RECOVERY_REQUIRED` with a sound
  state keep the agent resident; the recovery flag is boot-wide and never reset automatically.
* The boot inputs cached at bootstrap are re-read before every session and before any privileged
  step; a change refuses the session before a single frame is sent.
* Offline side: `--resident` mode in `native/target/ps4rfd_host.c` (with `--sessions`,
  `--idle-rounds`, `--no-refuse-while-busy`), `tools/hostctl/resident.py` as the per-session
  controller with a strict notice parser and a report-consistency check, and the driver's
  `--selftest` line is valid JSON now.
* Tests: `tests/harness/daemon_state_check.c` (production `ps4rf_daemon.c` without a socket) and
  `tests/test_w14_daemon.py` (26 tests: vocabulary, gate, notice/report documents, structural
  properties, and ten end-to-end scenarios, including the two session-scoped cases that must *not*
  end the agent). `native/target/build_manifest.py` gains `gate_agent_source()` — the
  comment-stripped, ELF-free source gate for "the agent names no kernel.read" plus the daemon's
  structural properties, wired into the manifest verdict and enforced by the suite.
