# S1.5 — independent Relapse review and adjudication

This review was run read-only in a delegated context after the S1.5 implementation and
measurement. The reviewer was given the claims to test, not their desired verdict. It performed
20 tool/API calls and did not modify the repository.

## Independent findings rechecked by the parent

* raw13g supports PS4 13.02, 13.04, 13.50 and 13.52 and labels the 13.52 state
  `663-LIVE-on-hardware … bug=663`.[1]
* syscall 663 is invoked as `aio_multi_wait` with five arguments.[2]
* local syscall-table slot 663 contains `0xffffffffd01eff50`, hence handler RVA `0x11ff50`, narg
  5; the independent local name table calls slot 663 `aio_multi_wait`.
* four 13.52-specific public RVAs resolve to the expected bytes/content in our image:
  `k_jmp_rsi 0x4d6d0`, `k_evf_cv 0x785228`, `k_idt_rsvd 0x1c1e00`, and
  `k_sysctl_handle_int 0x3fa8e0`. This is stronger than the two stable sysent/prison0 matches.
* the image is **NOT_PRISTINE**: it contains 26 known kpatch sites and syscall-table slot 11 points
  at the public `k_jmp_rsi` gadget. Layout identity does not imply file identity.
* raw13g's current tree and all Git history contain zero `relapse` strings. Raw13g proves the
  executable 13.52 chain and syscall identity, but does not self-attribute the family name.

## Adjudication of the apparent naming conflict

The independent reviewer initially left "Relapse applies to PS4 13.52" UNKNOWN because the
raw13g repository itself never says Relapse. A second source closes that exact attribution gap:
PSDevWiki names a PS4 AIO vulnerability "relapse", gives the range `?5.00?–13.52`, and credits
raw13g's 13.02–13.52 PS4 implementation.[3] Its exploit-chain table independently binds
`13.02–13.52 → relapse → slopkit → raw13g`.[4]

Therefore:

| claim | final verdict |
| --- | --- |
| raw13g itself uses the name Relapse | **REFUTED** |
| the public record attributes raw13g's PS4 13.02–13.52 chain to Relapse | **PROVEN** |
| our dump matches raw13g's 13.52 layout | **PROVEN** |
| our dump is pristine / byte-identical to the unpublished public ELF | **REFUTED** |
| syscall 663 is `aio_multi_wait` at local RVA `0x11ff50` | **PROVEN** |
| the vulnerable instruction or exact lifetime transition is byte-localised | **UNKNOWN** |
| PS4RF reproduced the historical root cause | **UNKNOWN** |
| Relapse is an unexposed blind case | **REFUTED** |

The last two UNKNOWNs remain binding. PSDevWiki explicitly has no implementation/write-up and
says that the bug description is still to be documented.[3] Matching the handler and producing a
rank-2 concurrency candidate is useful retrospective localisation, but not proof of the UAF,
race window, object lifetime, or primitive.
