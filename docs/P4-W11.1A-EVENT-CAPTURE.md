# P4 / W11.1A — Host EVENT Capture Debug (offline)

**Status: offline root cause found, fixed and proven. No live upload, no rearm, no console contact.
The W11.1 target payload is unchanged.**

## Question

The W11.1 live run behaved exactly as designed *except* for one thing: the sealed `boot.binding`
EVENT the console sent never reached the evidence (`boot_binding_event: null`), so the
classification W11.1 exists for was missing. The relay counted the console sending ~1 KB more than
in W11, so the bytes had left the console.

## Root cause

**The evidence assembly of the live runner dropped the already captured event — the reader was
fine.**

* Capture worked: `HostSession`'s single reader routed the EVENT into the event sink
  (`session.boot_binding`) in every run, live included.
* The offline runner copied the captured event into the evidence in its agent-stop branch
  (`if session.boot_binding is not None: ...`), the live runner did not:

  ```python
  # tools/hostctl/cli.py, live modes, before W11.1A (frozen bf21c98)
  except (SessionError, ProtocolError, EndpointClosed) as exc:
      rec.check('live session', False, str(exc))
      result = {'ok': False, 'bye': session.bye}
  ```

  Three lines, no capture. The event stayed in the session object and died with it. That is why
  the live evidence showed `null` while the console had demonstrably sent the event, and why the
  same payload captured it perfectly offline.

## Proof (offline replay of the live path, same host code)

`tools/hostctl/replay_live_capture.py` starts the W11.1 host agent on a loopback listener (same
sources as the payload, **not rebuilt for the payload**), drives the frozen sequence with
`drive(..., w11=True)` and forces the live outcome: both userland paths report nothing
(`BOOT_READ_FAILED`), the agent stops itself with BYE.

The frame order the replay produces is the live order, measured:

```
frame READY    (aead seq 0) -> router
frame RESPONSE (aead seq 1) -> router      (session.ping)
frame RESPONSE (aead seq 2) -> router      (session.status)
frame EVENT    (aead seq 3) -> router      -> event sink      <-- the boot.binding event
frame BYE      (aead seq 4) -> router      -> session lifecycle
```

The host was waiting for the response to `telemetry.read` when the EVENT and then the BYE arrived —
byte for byte the live failure ("agent closed the session (BYE BOOT_READ_FAILED) while waiting for
the response to telemetry.read").

| run | behaviour | event in the evidence |
| --- | --- | --- |
| `--legacy-live-behaviour` | pre-fix live branch, verbatim replica | **no** (`LEGACY_REPLICA_EVENT_LOST`), although the session had captured it (`events_seen: 1`) |
| default | current live branch (`live_agent_stop_outcome`) | **yes** (`PASS`), `boot_binding_verified.verified: true`, `no_boot_id: true`, frame sha256 recorded |

## Fix (host side only)

* `tools/hostctl/session.py` — **one central router**: `_recv_frame()` is the only socket reader;
  `_route()` dispatches by type (RESPONSE → request dispatcher, EVENT → event sink,
  BYE → session lifecycle). `request()` and `await_bye()` route through it instead of inspecting
  frames themselves. Event bookkeeping is explicit: `event_schema_rejected`, `unknown_events`,
  `duplicate_events`, `refused_events`, `events_before_bye`, plus an opt-in frame trace
  (`PS4RF_FRAME_TRACE=1`) that carries types, AEAD sequences, lengths, request ids and routing
  destinations — never key material.
* `tools/hostctl/cli.py` — **one shared capture helper** `capture_events()` and **one shared live
  stop outcome** `live_agent_stop_outcome()`, used by `drive()`, the offline self test and both
  live modes. The paths can no longer diverge: whatever the agent sent before its BYE reaches the
  evidence before the outcome is decided. A decisive diagnosis without a boot identity is still a
  successful W11.1 run; anything else is a failed live session.
* Fail closed, never silent: an EVENT in a session that did not negotiate event capture raises a
  `ProtocolError` (and is counted as refused); an unknown event type is kept as an opaque
  authenticated event; a known type failing its schema is recorded as `EVENT_SCHEMA_REJECTED`
  with the reason instead of a bare `null`; duplicates are defined (all copies kept, last one wins
  for the typed accessor, duplicate noted); a BYE never cuts the event queue.

## What this does *not* claim

* The **live** classification of the failed `KERN_BOOTTIME` read is still unknown. The replay uses
  the host stand-in (`both paths report nothing`), so its classes
  (`BOOT_SYSCTL_NAME_NOT_FOUND` / `BOOT_SYSCTL_MIB_NOT_FOUND`) are stand-in data, not console data.
  `BOOT_ID_UNVERIFIED` stays open; `kernel.read` stays `OPERATION_DEFERRED`.
* Whether a further W11.1 live run is justified is a review decision — the frozen payload and its
  custody are untouched, and its single rearm is consumed.
