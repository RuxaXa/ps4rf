# S1.8 — Base provenance recovery: findings and blockers

Frozen baseline: S1.7 = `364f9ac`, tag `s17-partial-baseline`.

## Where the 259 unattributed release sites actually break

Census over the 354 rank≤2 finding functions, every release-anchor call site with no object key.
The site IDs are `(function, site)` pairs and stay stable across runs.

| Terminal of the provenance chain | Sites | of which the object was known and lost |
| --- | --- | --- |
| `field_load` (base tracked or not) | 94 | **37** |
| `frame_slot` whose writer is outside the walk | 42 | 0 |
| no source operand identified | 27 | 0 |
| `indexed_load` | 16 | 1 |
| `global_pointer` | 16 | **16** |
| constant argument to the release | 12 | 0 |
| `argument` | 6 | 6 |
| never written / hop limit / return value | 4 | 0 |

The first-level census said "frame slot, 110 sites" and that was misleading: a refinement that
followed the spill to its writer found **0 of 34** slots that held a known value. Propagating frame
slots would have fixed nothing, because the slot contents were already unknown when spilled. The
frame slot is a transit, not a cause.

The real cause is the join: **60 sites** have an object that the model knew at the definition and
lost where control flow merges. That is the candidate this phase implemented.

## What was implemented (generic, nothing case-specific)

1. **A may-channel next to the definite value.** Every register carries the set of objects it may
   hold (cap 3). At a join the sets are unioned; an attribution made through the channel is
   `may`-strength, never `must`. This is what a definite-value lattice cannot express: on the path
   that reaches the release, the object *is* the one that was tracked.
2. **Copy-on-write state clones.** The may-channel was initially shared between state copies, so
   writing one path's value rewrote its sibling's and collapsed two candidates into one. Found by a
   failing negative fixture, fixed with `_clone_state`.
3. **Caller-saved registers do not survive a call.** `rdi`, `rsi`, `rdx`, `rcx`, `r8`–`r11` and `rax`
   are cleared at every call. Keeping them is how a stale object gets "released" on paper.
4. **Release attribution from the merged per-site state.** A site is visited once per traversal, and
   an early traversal can see a single candidate that a later one reveals to be one of several.
   Attribution therefore reads the *union* of all traversals at that site: exactly one object ⇒
   attribute (strength `may` unless every traversal was definite); two or more ⇒ refuse.
5. **Release sites are labelled with the argument the release consumes.** `_release_sites` took the
   last `mov` into any argument register, so `fdrop_release` sites were labelled `rbp-0x68` (`rsi`,
   a context pointer) instead of the object in `rdi`. The slot that was really freed stayed invisible
   and its NULL reset could never count as a kill.

## Blocked and deliberately not landed: conditional branch targets

`FunctionView._build_cfg` uses `_direct_target` in the default mode, which returns a target **only
for `call` and `jmp`**. Every conditional branch therefore loses its taken edge: the alternative
path never joins, values stay "definite" across a branch, and must-strength claims rest on a CFG
that does not contain the branch.

Measured consequence of restoring the edges (`_branch_target` for all `j*`):

* newly attributed release sites rise from **17 to 55** of 259 — the defect hides 38 real flows;
* `D2_double_release` then claims a kill-free path on the **fixed** 13.52 `aio_multi_delete` body
  (`0x11f710`, release sites `0x11fda9`/`0x11fe1b`, rank 1) — a false positive on the labelled
  negative, because it cannot distinguish two release sites that belong to different loop exits.

Landing the CFG correction without reworking that detector would trade a blind rule for a wrong
one, which the phase rules forbid ("no soundness regression"). The edge is therefore left as it is,
with a comment in `patterns.py` pointing here. **This is the concrete blocker for the next phase:**
restore the branch targets and rework `D2`'s kill/slot semantics in the same step.

direction:
