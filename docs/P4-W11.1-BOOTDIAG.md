# P4 / W11.1 — Userland `KERN_BOOTTIME` diagnostics (offline)

Status: **offline complete, built and proven; live run pending the BinLoader rearm.**

## 1. Goal

W11's live run ended in a clean, fail-closed `BOOT_READ_FAILED`: the userland boot collector could
not produce a complete `struct timeval` for `KERN_BOOTTIME`. W11.1 exists to find out *why*, still
**entirely in userland**:

* no `kexec`, no `rdmsr`, no kernel address, no RVA sent to the host, no `kernel.read`,
* no capability promotion, no contract downgrade, no guessed value.

## 2. Two access paths, instrumented

Both go through the libPS4 userland wrappers exactly as declared in the SDK
(`libPS4/include/kernel.h`, resolved from `libKernelHandle`):

* **Path A** — `sysctlbyname("kern.boottime", ...)`
* **Path B** — direct MIB: `sysctl({CTL_KERN = 1, KERN_BOOTTIME = 21}, 2, ...)`

Per path, in this order:

1. **size query only**: `oldval = NULL`, `oldlen = &len` → recorded: return code, errno, reported
   length. No interpretation.
2. **bounded read** (only when the size query answered): buffer of at most **64 bytes**
   (`PS4RF_BOOTDIAG_MAX_BYTES`), `newval = NULL, newlen = 0` (read-only), recorded: return code,
   errno, requested size, returned `oldlen`, raw bytes — and *only* those bytes.

`errno` is read through the SDK's `__error()` hook with a NULL check; the event records whether
errno was observable at all (`errno_observable`) instead of inventing a value.

## 3. ABI evidence (checked offline, recorded in the manifest)

| item | value | source |
|---|---|---|
| `sysctl` | `int (*)(int *name, unsigned namelen, char *oldval, size_t *oldlen, char *newval, size_t newlen)` | `kernel.h` |
| `sysctlbyname` | `int (*)(char *name, char *oldval, size_t *oldlen, char *newval, size_t newlen)` | `kernel.h` |
| `oldlen` type | `size_t *` (8 bytes, target) | `kernel.h` |
| `time_t` / `suseconds_t` | `int64_t` / `long` (8 / 8 bytes) | `types.h` |
| `struct timeval` | `{tv_sec, tv_usec}` → **16 bytes**, align 8 | `types.h` + kernel image |
| kernel side | the pinned FW13.52 image stores the same 16 byte `timeval` at RVA `0x224c6c8` (`sec` + `usec`, both 8 bytes LE) | W10 analysis |

The console implementation carries `_Static`-style asserts (`ps4rf_bootdiag_timeval_is_16`,
`..._is_aligned`) so a target where the layout differs **fails to compile**; the manifest also
records `timeval_sizeof` from the event, and the host **refuses any binding** if it is not 16
(`ABI_MISMATCH`). The contract is therefore never silently downgraded.

## 4. Classification (measured values only)

Per method, in the event: `method, size_query_attempted, size_query_rc, size_query_errno,
reported_size, read_attempted, read_rc, read_errno, requested_size, returned_size, raw_len,
raw_max_bytes, raw_sha256, raw_hex, classification, classification_id`.

| class | rule |
|---|---|
| `BOOT_SYSCTL_NAME_NOT_FOUND` | size query or read failed with `ENOENT` on path A |
| `BOOT_SYSCTL_MIB_NOT_FOUND` | size query or read failed with `ENOENT` on path B |
| `BOOT_SYSCTL_PERMISSION` | `EPERM` / `EACCES` |
| `BOOT_SYSCTL_INVALID_ARGUMENT` | `EINVAL` |
| `BOOT_SYSCTL_SIZE_QUERY_FAILED` | size query failed with any other errno, or no read was attempted |
| `BOOT_SYSCTL_READ_FAILED` | read failed with any other errno |
| `BOOT_SYSCTL_SHORT_RESULT` | `returned < 16` bytes |
| `BOOT_SYSCTL_MALFORMED_RESULT` | 16 bytes, but `tv_sec <= 0` or `tv_usec` outside `0..999999` |
| `BOOT_SYSCTL_SUCCESS` | complete, in-range 16 byte timeval |

The host **re-derives** every class from the raw numbers and compares it with the console's claim
(mismatch = evidence problem), and re-computes `raw_sha256` over the reported bytes.

## 5. Contract rules

* Only a **complete 16 byte timeval** can become a boot identity. 8 bytes → `BOOT_SOURCE_PARTIAL`,
  no boot id, and the 8 bytes are **never** assumed to be `tv_sec`.
* Both paths complete → bytes must be identical, else `BOOT_SOURCE_CONFLICT`, no boot id.
* One path complete and the sibling answered with unusable bytes (short/malformed) →
  `BOOT_SOURCE_CONFLICT`, no boot id. A sibling that did not answer at all (not found, permission,
  invalid argument, read failed) does not block the working path.
* Only the MIB form working is acceptable: it then becomes the **preferred boot source contract**
  and `sysctlbyname` is documented as unsupported on this firmware.
* Second reading after a bounded pause (`PS4RF_BOOT_PAUSE_US`): only with a complete timeval;
  differing values → `BOOT_SOURCE_NOT_STABLE`, no boot id.
* No random fallback, ever. On any of the above the agent ends the session itself with the status
  name as the BYE reason.

| both complete, identical | SUCCESS / SUCCESS | OK | `BOOT-19d2c790b0769502` |

| both complete, different | SUCCESS / SUCCESS | `BOOT_SOURCE_CONFLICT` | none |

Every row is a **verified diagnosis**: the host re-derives the classes, the derived run status
matches the console's, and a diagnosis-only run counts as a successful W11.1 run (the boot binding
itself is *not* required for W11.1 to succeed). Unit level: `tools/hostctl/boot.py --self-test`
(8 rejection mutations + the valid event + 6 diagnosis cases + drift + only-MIB contract).

## 8. Live preparation

* Sequence: handshake → `session.status` → size query + bounded read (A) → size query + bounded read
  (B) → stability read if complete → sealed `boot.binding` event → final `session.status` → BYE →
  health. No retry.
* BinLoader rules unchanged: no port check, no probe connect, no scan, no `curl`/`nc` against 9090
  before an explicit rearm confirmation; then **exactly one** upload.
* A decisive classification of the earlier failure — `SHORT_RESULT`, `PERMISSION`, `NOT_FOUND`,
  whatever it measures — completes W11.1. If both paths fail or only return partial data, that is
  reported and the next candidate (W11.2, a bounded privileged read of the 16 bytes at
  `kbase + 0x224c6c8`) needs its own review first.

## 9. Findings (W11.1)

* **F1** — the W11 live failure is explained by the *instrumented* run only; the old collector could
  not distinguish "call failed" from "short answer". W11.1 records both.
* **F2** — a sibling path that returns bytes which cannot be a timeval is treated as a conflict, not
  as a usable source; this is stricter than the mandate and errs on the safe side.
* **F3** — `errno` is observable on the target only through `__error()`; the event says so
  explicitly instead of assuming an errno value.
* **F4** — the payload contains no raw `syscall` instruction at all (whole image), which makes the
  "no kexec / no syscall 11" claim structural rather than source-only.
