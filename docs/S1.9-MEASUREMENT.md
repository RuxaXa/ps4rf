Every number below was produced on the same machine (Hermes LXC, unprivileged), against two
trees: the frozen S1.8 baseline `f1be50e` in a separate worktree
(`/home/hermes/.hermes/cache/scratch/ps4rf-s18-base`) and the S1.9 working tree
(`/home/hermes/work/ps4rf-a1`). Comparison is always by identifier — function RVA, release
site, chain identity — never by finding count alone.

Image: `kernel.bin` FW 13.52, SHA-256
`cf157ffdbae872a20bbb9a46c8518b53d96c1ed75d4e73878466a295d92eca35`, `NOT_PRISTINE`

## 5. D3 path witnesses (P2)

After the correction D3 produced 39 findings that did not exist before. Their 158 stores were
checked one by one for an explicit path from the entry that never enters a lock block:

* 152 stores: witness path found (example `0x125db0`, store `0x125e9e`:
  `0x125db0 → 0x125dce → 0x125e2e → 0x125e8f → 0x125e9e`, avoiding lock calls
  `0x125e78` and `0x125ed1`),
* 0 stores in unreachable blocks,
* **6 stores: no lock-free path.** Every path took a lock, but in *different* blocks, so the
  dominance reading D3 used called them uncovered.

D3 now reads coverage as a path property. Re-measured: 38 findings, 152 stores on a lock-free
path, 0 in unreachable blocks, 0 without a witness.
