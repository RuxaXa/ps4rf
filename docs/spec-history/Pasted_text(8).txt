1. BoundedPool Deadlock entfernen

Aktuell ruft `_worker()` innerhalb:

with self._lock:

`_finalize()`

auf, das denselben nicht reentranten Lock erneut nimmt.

Das deadlockt.

Canceled Entscheidung unter Lock treffen, Lock verlassen und erst danach `_finalize()` aufrufen.

Beispielsemantik:

with lock:
    state = ...

if canceled:
    finalized = _finalize(...)
    if finalized:
        on_canceled(...)
    continue

Kein interner Aufruf einer Lock nehmenden Methode während derselbe Lock gehalten wird.

Die aktuelle Token Acquire Zeile ebenfalls vereinfachen.

Nicht:

if not self._tokens._semaphore.acquire(...) if False else ...

sondern ausschließlich öffentliche API:

if not self._tokens.acquire(blocking=False):
    return TOO_MANY_INFLIGHT

2. Worker Lifecycle wirklich mit äußerem finally absichern

Aktuell verlassen:

MockHangReleased
BudgetExceeded
UNEXPECTED_AT_POISON

den Worker per return bevor:

reqs.complete(rid)

erreicht wird.

Neue Struktur:

def _worker_run(...):
    suppress_response = False
    try:
        try:
            resp = dispatch(...)
        except MockHangReleased:
            evidence HANG/NO_RESPONSE
            suppress_response = True
        except BudgetExceeded:
            abort_on_budget(...)
            suppress_response = True
        except Exception:
            ...
        if not suppress_response:
            respond(...)
    finally:
        pool.finish(rid)
        reqs.complete(rid)

Token und Request ID werden auf JEDEM Pfad exakt einmal finalisiert.

budget abort → kein pending RID
exception during dispatch → kein pending RID

2. Selbstprüfpass — zwei echte Fixes
Fix A (freeze-relevant): submit↔poison Race in submit()

Die v0.8-Fassung prüft _poisoned unter einem ersten Lock, acquiriert dann den Token und registriert erst unter einem zweiten Lock. Ein poison() zwischen Check und Registrierung ließe einen nach dem Poison eingereichten Request als QUEUED registrieren — er würde ausgeführt, obwohl V5 verlangt: keine neuen mutierenden Requests nach Poison. Korrektur: Re-Check unter dem Registrierungs-Lock.
python
 
  
 
 
def submit(self, rid: str, op: str, fn) -> str:
    # B1: ausschließlich öffentliche Semaphore-API
    if not self._tokens.acquire(blocking=False):
        return "TOO_MANY_INFLIGHT"
    with self._lock:
        if self._poisoned:                    # FIX A: Re-Check schließt das Rennen
            self._tokens.release()            # Token zurück, kein Leak
            return "POISONED"
        self._tasks[rid] = {"state": TaskState.QUEUED, "op": op}
    self._queue.put((rid, op, fn))
    return "OK"
 
 

Damit ist das Fenster geschlossen: Registrierung vor Poison → poison() markiert CANCELED_AT_RECOVERY; Registrierung nach Poison → hier abgelehnt. Kein dritter Fall.
