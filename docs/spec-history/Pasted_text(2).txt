2. K2 — Capability State: Availability × Assurance

Die eindimensionale Rangliste wird gestrichen. Zwei orthogonale Achsen:
text
 
  
 
 
Availability (aktueller Session-Befund):  UNKNOWN, AVAILABLE, DEGRADED, UNAVAILABLE
Assurance   (Beleggrad der Aussage):      UNVERIFIED, OBSERVED, PROVEN
 
 

Normative Conflict Resolution — angewendet pro Capability, nur zwischen Records mit gleichem scope und gleichem context:
text
 
  
 
 
1. MANUAL            manuelle Entscheidung gewinnt immer, wird geloggt
2. SESSION_SCOPE     fremde Scopes/Contexte kollidieren nicht (Separation, kein Konflikt)
3. PROVIDER_AUTHORITY pro Achse: Provider mit höherer Authority gewinnt für seine Achse
4. AVAILABILITY_OVERRIDE  bei gleicher Authority: aktueller Runtime-Befund
                     (UNAVAILABLE/DEGRADED, neuerer created_at) schlägt älteres
                     AVAILABLE — Availability ist immer "Session-Wahrheit jetzt"
5. EVIDENCE          für Assurance: PROVEN(mit verified_by) > OBSERVED > UNVERIFIED;
                     Assurance verfällt NICHT durch Recency allein innerhalb der Session
6. RECENCY           letzter Tie-Breaker
 
 

Effektive Grant-Regel:
text
 
  
 
 
granted  ⇔  context match
        ∧  availability == AVAILABLE  (∨ DEGRADED && allow_degraded)
        ∧  assurance >= min_assurance_for_grant (Namespace-Regel, privilegiert: PROVEN)
 
 

Wichtige Konsequenz, explizit festgehalten: PROVEN + aktuelles UNAVAILABLE = nicht granted. Assurance ist die historische Belegqualität, Availability die aktuelle Verwendbarkeit — genau der Fall „alter Exploit-Befund vs. aktuelles Probe-Ergebnis".

Schema-ä.forceerbare Regeln:
text
 
  
 
 
assurance == PROVEN            → evidence + verified_by Pflicht (if/then)
verified_by.operation          → Pattern "^verify\."  (Verifikation nur durch
                                 dedizierte PS4RF verify.*-Primitive; §76/K-Metasploit)
provider_type == RUNTIME_PROBE → assurance nur UNVERIFIED|OBSERVED (if/then)

4. K4 — Session Key Transport (gehärtet)

Normativ:
text
 
  
 
 
1. Secret: 256 Bit CSPRNG, genau einmal vom Bootstrap Provider injiziert
   (Payload-Argumentblock bzw. WebKit-Content-Parameter).
   VERBOTEN: URL, Query-String, Dateiname, Log, Evidence, Crash-Dump (x-secret).

2. Nonces: agent_nonce, host_nonce je 128 Bit Zufall (HELLO / HELLO_ACK).

3. Transcript T  = "ps4rf-handshake-v1" || session_id || nonce_agent || nonce_host
   k_hs          = HKDF-SHA256(ikm=secret, salt=nonce_agent||nonce_host,
                               info="ps4rf/handshake-v1", L=32)
   proof_agent   = HMAC-SHA256(k_hs, T || 0x41)
   proof_host    = HMAC-SHA256(k_hs, T || 0x48)
   Mutual Proof: Agent weist sich in AUTH, Host in AUTH_ACK.
   Session gilt erst nach beidseitigem Proof als ACTIVE.

4. Schlüssableitung (Rohkey wird danach NIE direkt verwendet):
   k_aead = HKDF-SHA256(secret, salt, "ps4rf/rpc-aead-v1", 32)
   HKDF-Info-Registry für künftige Schlüssel; keine Wiederverwendung desselben
   Rohkeys für MAC und Verschlüsselung.

5. Wire: AEAD-framed. v1 Default AEAD_CHACHA20_POLY1305 (RFC 8439),
   optional AES_256_GCM. Nonce = 96 Bit = 32-Bit-Richtungspräfix (aus HKDF,
   "ps4rf/nonce-prefix-v1", je Richtung) || 64-Bit-Sequence (BE).
   AAD = kanonischer Header (protocol_version, session_id, sequence, direction).
   Die Sequence ist damit authentifizierte Daten. Replay → REPLAY_DETECTED
   und Session-Abbruch (AUTH_FAILED).

5. K5 — Canonicalization: RFC 8785 (JCS)

Verbindlich:
text
 
  
 
 
Alle kanonischen Hashes (Experiment, Profile bundle.canonical_sha256,
Evidence-Kanonisierung, IR) = SHA-256 über die RFC 8785 (JCS) Serialisierung
(UTF-8, Keys sortiert nach UTF-16 Code Units, ES6-Zahlenformat).

ir_encoding / canonical_encoding v1 = "jcs-rfc8785". Kein eigenes Format.
 
 
json
 
  
 
 
"canonical_encoding": { "enum": ["jcs-rfc8785"] }
 
 

experiment.schema.json: "ir_encoding": { "$ref": "common.schema.json#/$defs/canonical_encoding" }.

Cross-Implementierungs-Pflicht (Tests, Schritt d): Golden Vectors mit mindestens: verschachtelte Key-Sortierung, Unicode-Keys (BMP + Non-BMP), Float-Edgecases (1.0, 1e21, -0.0 → JCS-Normalform), leere Container, große Integers. Python-Seite Referenzimplementierung rfc8785 (PyPI); jede künftige C-Implementierung im Agent-build muss gegen dieselben Vectors bestehen, bevor sie Hash-Autorität erhält.

Verbindlicher Vertrag für kernel.snapshot mit explicit-Range:
text

9. K9 — Session States inkl. RECOVERY_REQUIRED

Verbindliche Session State Machine:
text
 
  
 
 
NEW → HANDSHAKE → ACTIVE → DRAINING → CLEANUP → CLOSED
                       │          │
                       └──────────┴──→ RECOVERY_REQUIRED → (Recovery/Reboot) → CLOSED
 
 
json
 
  
 
 
"session_state": { "enum": ["NEW", "HANDSHAKE", "ACTIVE", "DRAINING",
  "CLEANUP", "RECOVERY_REQUIRED", "CLOSED"] }
 
 

Regeln:
text
 
  
 
 
Übergang nach RECOVERY_REQUIRED: Cleanup wegen blockierendem Kernel Call,
Hang-Suspect oder nicht wiederherstellbarem Resource-Zustand nicht möglich.

In RECOVERY_REQUIRED (konsoleweit, überlebt Session-Ende):
  - HELLO wird akzeptiert, nur Read-Only-Operationen erlaubt
    (session.ping, session.status, Telemetry-Lesezugriff)
  - jede mutierende Operation → SESSION_RECOVERY_REQUIRED
  - KEINE neue mutierende Session bis Recovery bzw. Reboot und neuer
    Capability Negotiation (volatile Capabilities sind ohnehin fällig)
 
 

Schema-Folgen: common.error_code += SESSION_RECOVERY_REQUIRED; bye.reason += RECOVERY_REQUIRED; neues session_status_result:

"""ORBP-INV: statischer Inventar-Extraktor für OrbisProbe (kein Code wird ausgeführt)."""
import ast, re, sys
from pathlib import Path

HEX    = re.compile(r"\b0x[0-9a-fA-F]{6,16}\b")

TOOLS  = re.compile(r"(?i)(ghidra|rizin|radare2?|angr|unicorn|afl|syzkaller|boofuzz|scapy|tshark|wireshark|mitmproxy)")
SECRET = re.compile(r"(?i)(password|token|secret|api[_-]?key)")

TAGS = ((HEX, "hexconst"), (FWVER, "fwversion"), (PS4KW, "ps4keyword"),
        (LIVE, "liveexec"), (SAFETY, "safety"), (REPORT, "reporting"),
        (TOOLS, "tool"), (SECRET, "secret"))

def scan_py(p: Path, acc: dict):
    src = p.read_text(errors="replace")
    try:
        tree = ast.parse(src)
    except SyntaxError:
        acc["hits"].append(f"{p}:0 [PARSE_ERROR]")
        return
    acc["modules"].append(str(p))
    for n in ast.walk(tree):
        if isinstance(n, ast.ClassDef):
            bases = ",".join(ast.unparse(b) for b in n.bases)
            acc["classes"].append(f"{p}:{n.lineno} class {n.name}({bases})")
        elif isinstance(n, (ast.FunctionDef, ast.AsyncFunctionDef)):
            args = ", ".join(a.arg for a in n.args.args)
            acc["functions"].append(f"{p}:{n.lineno} def {n.name}({args})")
        elif isinstance(n, ast.Import):
            acc["imports"] |= {a.name for a in n.names}
        elif isinstance(n, ast.ImportFrom) and n.module:
            acc["imports"].add(n.module)
    for i, line in enumerate(src.splitlines(), 1):
        for rx, tag in TAGS:
            if rx.search(line):
                acc["hits"].append(f"{p}:{i} [{tag}] {line.strip()[:140]}")
    if "__main__" in src:
        acc["entrypoints"].append(str(p))

def scan_generic(p: Path, acc: dict):
    src = p.read_text(errors="replace")
    for i, line in enumerate(src.splitlines(), 1):
        for rx, tag in TAGS:
            if rx.search(line):
                acc["hits"].append(f"{p}:{i} [{tag}] {line.strip()[:140]}")

def main(root: str):
    root = Path(root)
    acc = {k: [] for k in ("modules", "entrypoints", "classes", "functions",
                           "imports", "hits")}
    tests = []
    for p in sorted(root.rglob("*")):
        if not p.is_file() or any(x in p.parts for x in (".git", "venv", "__pycache__")):
            continue
        if p.name.startswith("test_") or p.name.endswith("_test.py"):
            tests.append(str(p))
        if p.suffix == ".py":
            scan_py(p, acc)
        elif p.suffix in (".c", ".h", ".cpp", ".hpp", ".sh", ".yaml", ".yml", ".json"):
            scan_generic(p, acc)
    for p, keys in ((root / "pyproject.toml", ("scripts",)),
                    (root / "setup.py", ("entry_points",)),
                    (root / "setup.cfg", ("console_scripts",))):
        if p.exists():
            acc["entrypoints"].append(f"[manifest] {p}")
    out = Path("ORBISPROBE-INVENTORY.draft.md")
    with out.open("w") as f:
        f.write("# ORBISPROBE-INVENTORY (draft, statisch extrahiert)\n\n")
        for title, key in (("Module", "modules"), ("Entry Points", "entrypoints"),
                           ("Klassen", "classes"), ("Funktionen", "functions")):
            f.write(f"## {title} ({len(acc[key])})\n\n```\n" +
                    "\n".join(acc[key]) + "\n```\n\n")
        f.write("## Imports (extern)\n\n```\n" +
                "\n".join(sorted(i for i in acc["imports"]
                                 if i.split(".")[0] not in sys.stdlib_module_names)) +
                "\n```\n\n")
        f.write("## Befunde (Hex/FW/PS4/Live/Safety/Tools/Secrets)\n\n```\n" +
                "\n".join(acc["hits"]) + "\n```\n\n")
        f.write(f"## Tests ({len(tests)})\n\n```\n" + "\n".join(tests) + "\n```\n")
    print(f"OK -> {out}")

if __name__ == "__main__":
    main(sys.argv[1] if len(sys.argv) > 1 else ".")

12.3 Provider-Registrierung

Exploit-Name: metasploit:<msf-refname>. Das PS4RF-Manifest (exploit.schema, Lieferung 2) definiert weiterhin vollständig: requires, provides, target/profile_bindings, execution (aus exploit_execution_context), preconditions (§75), verification (verify.*-Operation), cleanup, reliability, side_effects. Kontext-Mapping:
text
 
  
 
 
exploit/ps4/browser/*  → prepare HOST, trigger WEB_CONTENT, verify USERLAND_AGENT
auxiliary/ps4/*        → HOST
post/ps4/*             → USERLAND_AGENT | SYSTEM_SERVICE (je Session-Typ, deklariert)
 
 

Capability-Regel (schema- und datengetrieben): Ein MSF-Module-Run erzeugt höchstens assurance = OBSERVED (Availability-Signale erlaubt). PROVEN entsteht nur durch einen separaten PS4RF-Verifikationslauf mit verified_by.operation ∈ verify.* und verification_run != trigger_run — durchgesetzt via provider_pattern: "^metasploit:" in authority.json plus dem globalen ^verify\.-Pattern auf verified_by.operation (K2). Beispielfluss:
text

→ Safety Gates → module_check → module_run → SUCCESS + Session
→ userland.exec, assurance=OBSERVED, provider=metasploit:…
→ START_AGENT / EXECUTE_BUFFER-Nonce über Session
→ verify.userland.exec PASS → userland.exec, PROVEN (neuer Record, neuer Run)
