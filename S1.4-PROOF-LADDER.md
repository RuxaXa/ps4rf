# S1.4 — proof ladder, privilege reachability, object flow

**Why this exists.** In S1.3 a chain had one word for "the hops have witnesses": `proved`.
That word was being read as "there is a bug you can use", and the measurement said otherwise —
254 of 254 proved chains carried `REQ_UNPRIV_ENTRY: OPEN`. S1.4 replaces the word with a
ladder that stops where the evidence stops.

## The five levels (`chains.PROOF_LEVELS`)

| level | what it asserts | what clears it | clearable offline? |
| --- | --- | --- | --- |
| `CFG_REACHABLE` | a witnessed control-flow path from a resolved entry reaches the function | `REQ_ENTRY_REACHABLE`; every hop proved | yes |
| `UNPRIV_REACHABLE` | that path is usable by an unprivileged caller | `REQ_UNPRIV_ENTRY` with recorded evidence (device-record mode, or a read handler path with no credential gate) | only with evidence; today mostly no |
| `OBJECT_FLOW_PROVEN` | the object the primitive acts on is the one the entry supplies, and ownership actually passes between functions | `REQ_OBJECT_FLOW` — alias-tracked identity plus a callee-side use; **a call edge never clears it** | yes, intra-function and one call deep |
| `PRIMITIVE_VALIDATED` | every primitive-specific precondition holds (spray, two contexts, race widening, vtable, length, copy site, …) | the union of the primitive's `requires` | partly; the live ones never |
| `EXPLOIT_CHAIN_VALIDATED` | the chain repeats on the target well enough to turn a bug into control | `REQ_CHAIN_STABILITY` — a measured success rate | **no, by construction** |

A chain sits on the highest rung whose obligations are *all* met. The rung above it is
published as `next_obligation`, with the missing requirement ids and the text that says what
would clear them. A requirement that was never evaluated counts as open: an unknown obligation
must not be inherited as a met one.

`proof_ladder_for(bug_class)` computes the requirement sets per level; `proof_level_for()` walks
them. `Chain.proof_level`, `Chain.obligations` and `next_obligation` are in every chain artefact,
and the per-artefact totals are in `counts.proof_levels`.

**What the ladder forbids.** No finding may be reported as exploitable below
`PRIMITIVE_VALIDATED`, and `EXPLOIT_CHAIN_VALIDATED` cannot be reached offline at all — it needs
a measurement on hardware. A produced chain that reads `CFG_REACHABLE` says one thing: the code
is reachable. That sentence is now the type of the record, not an interpretation of a word.

## Privilege reachability (`authz.py`)

Three separate questions, only two of which an image can answer:

1. **Dispatch (answerable).** `resolve_syscall_dispatch()` reads `sysent[n].sy_call` at
   `table_rva + n*48 + 8`, converts the kernel VA to an RVA through `image.base`, and keeps only
   handlers that land inside the image. Same for `cdevsw` via the recorded record layout. The
   evidence is the table slot and the pointer that was read.
2. **A gate that exists (partly answerable).** `find_credential_gates()` walks the handler path
   and records references to the `prison0` credential context and calls to authorization symbols
   *if the firmware resolves them*. A hit is positive evidence: `PRIVILEGED`.
3. **Absence of a gate (not answerable here).** The anchor set for FW 13.52 contains `malloc`,
   `free`, `printf`, `mtx_lock`, `sx_xlock`, `fdrop_release` — **no** `priv_check_cred`,
   `kauth_cred_issuser`, `suser`, `p_cansee`. So "no gate found in the walk" is a statement
   about the walk. Every such entry is `UNKNOWN` with the missing obligation recorded:
   *resolve the authorization symbols, or supply the device-record mode*.

`UNPRIVILEGED` is therefore returned only when a facts record supplies a basis **and** evidence
(e.g. a device mode). A claim without evidence returns `UNKNOWN`, never `UNPRIVILEGED`.

## Object flow (`objectflow.py`)

The rule: **a call edge is not a transfer.**

* `track_register()` builds an alias closure inside one function — `mov`/`movzx`/`movsxd`/`movsx`,
  `lea` (interior pointer), stack spill and reload through a fixed frame slot, and an `xor reg, reg`
  that ends the alias.
* `object_field_writes()` turns the alias into field writes with offsets. This is where the
  repaired store summary earns its keep: an identity claim that names `[base+0x28]` is checkable;
  one that names a register is not.
* `prove_transfer()` requires **both** a tracked alias in a System V argument register before the
  call **and** a callee-side use of that argument (dereference or handoff). Missing either half
  returns `proved: False` with the reason — no edge status is invented.
* `object_flow_for_drops()` answers the identity question for the sites inside one function and
  reports the shared field offsets that back it. `analyse_finding()` assembles it from
  `handles.release_shape` plus `handles.summarize(...).stores`, so `stores` now has a consumer.

## Gaps this documents rather than hides

1. **Authorization symbols are unresolved.** Without them, level 2 is out of reach for most
   entries — the ladder records it instead of assuming it.
2. **Object identity is intra-function plus one call deep.** Multi-hop ownership (acquire in A,
   drop in C via B) needs a summary per function; the graph carries `transfers-reference` edges
   only where the argument provenance is proved, and the rest stay `unknown`.
3. **No IPC dispatch.** Only `sysent` and `cdevsw` are resolved; a message-passing entry would
   need its own table, and none is in the facts yet.
4. **`PRIMITIVE_VALIDATED` is not "the bug is real".** It means the modelled preconditions for
   the primitive hold; whether the detector's premise is right is a separate question that no
   level in this ladder answers.
