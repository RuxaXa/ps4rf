# S1.7 — Indexed Object Identity: frozen hypothesis and acceptance test

Frozen before any analysis run of this phase. Baseline: S1.6 = `d8de635` (tag `s16-partial-baseline`),
accepted as PARTIAL.

## Hypothesis h2

In FW 13.52 at least one of the 229 unattributed release sites releases a **specific slot of a
specific table**, and that identity is reconstructible from bytes alone:

* **table instance** — the base is a global object reached by `lea`/`mov` from a rip-relative
  address, or an object reached from an argument;
* **index expression** — `[base + index*scale + disp]` with the scale and displacement recorded;
* **index provenance** — the index register holds a value whose origin is an *argument* or a
  *constant*; a value reloaded from memory, transformed by arithmetic, or produced by a call is
  **not** a provenance;
* **stored pointer** — the load is the value released, so the object is the slot's content, not the
  table and not the argument.

Identity is claimed only when table instance, index expression and object generation agree. Equal
object *class* ("an element of table X") is explicitly **not** identity.

## Acceptance test (all four must hold)

1. **Concrete instruction witness on FW 13.52** — at least one element key
   `("tab", table_rva, index_provenance, disp)` with the load instruction address and the release
   site it feeds, from the 229 previously unattributed sites.
2. **Fixture differential** — same table + same index + unchanged generation ⇒ same object (a double
   release is reported); different index ⇒ no claim; a store into the slot between two reads ⇒ no
   claim (new generation); unresolvable index ⇒ no claim.
3. **S1.6 negative controls stay negative** — the three same-caller/other-callee and three
   other-argument-register edges remain `REFUTED`.
4. **Soundness of the REFUTED ownership verdicts** — a body whose walk is "complete" but which
   contains unresolved object accesses may hide a consumption, so it must yield `UNKNOWN`, not
   `REFUTED`. Measured as a reduction of the 201 `REFUTED` chains, reported with the reason.

## Search space and budget

* Reconstruction sample: **at most 20** of the 229 unattributed sites, chosen by first occurrence
  per distinct calling function — no full sweep.
* Implementation stays inside the existing per-body budgets (`MAX_BLOCKS` 240, `MAX_STEPS` 20'000,
  `MAX_ITERATIONS` 6, `MAX_PATH` 2).
* One final measurement run only, with wrapper identification and the coverage stage timed
  separately.
* Full regression only at the integration point.

## Result (appended after the runs; the text above is unchanged)

* Criterion 1 — **partially met**. Two instruction-level slot identities were found, but they come
  from the wider 1'200-function closure, **not** from the 229 target sites. The 229 remain
  unattributed: their blocker is base provenance, not index provenance.
* Criterion 2 — **met**. Six fixture cases, positive and negative, byte-pinned.
* Criterion 3 — **met**. 3 same-caller and 3 other-register controls still `REFUTED`, `SUPPORTED`.
* Criterion 4 — **met**. The gate withdraws 119 unsupported `REFUTED` verdicts to `UNKNOWN`.

Phase verdict: **PARTIAL**. See `S1.7-MEASUREMENT.md` and `S1.7-SOUNDNESS-REFUTED.md`.
