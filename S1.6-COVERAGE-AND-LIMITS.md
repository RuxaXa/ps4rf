# S1.6 P5 — Coverage, recall, false positives, unresolved boundaries

All numbers from the runs documented in `S1.6-MEASUREMENT.md`. No number here is an estimate.

## Code coverage of the analysis

| metric | value |
|---|---|
| functions summarised (rank ≤ 2 findings + callees) | 1'171 |
| bodies walked completely (`complete`) | 638 (54.5 %) |
| truncated but usable (`partial`) | 530 (45.3 %) |
| refused outright | 3 (0.3 %) |
| direct call sites in the image (reverse index) | 106'111 |
| distinct call targets | 9'859 |
| call edges judged as transfers | 52 caller summaries over 153 consuming functions |

`partial` is dominated by indirect calls and by the per-body budgets (`MAX_BLOCKS` 240,
`MAX_STEPS` 20'000, fixpoint `MAX_ITERATIONS` 6). Those budgets are deliberate: a body that cannot
be walked within them is *refused*, never half-claimed.

## Ownership recall

Two different questions, deliberately separated:

1. **Recall on objects that flow from arguments** — measured, low: 7 of 266 release-anchor call
   sites inside the audited functions have an attributable object in the argument register (2.6 %).
2. **Recall given a container that owns the object** — this is where the layer works: 153
   functions consume a reference on an object reachable from an argument, and 12 caller edges pass
   such an object into them with both witnesses.

The gap between the two is the honest headline: the layer sees *fields of* arguments well and
*argument-passed objects* rarely, because this kernel fetches releasable objects from global tables
and callee results.

## False positives — known, fixed, and pinned

* **Guarded release reported unguarded.** `lock xadd [obj+off], eax; cmp eax, 1; jne` — the `xadd`
  leaves the previous count in `eax`, so the compare *is* the guard. The guard prover never seeded
  the `xadd` destination, so a correctly guarded release was reported unprotected. Fixed; pinned by
  `test_a_lock_xadd_drop_with_a_count_test_is_guarded`.
* **Conditional release reported unconditional.** A `je` jumping over the release into the same
  basic block satisfied block dominance. Fixed by `_skipped_by_branch`; pinned by
  `test_a_release_on_one_arm_is_conditional`.
* **Container inheriting the field's life cycle.** A drop on the pointer stored at `arg0+0x30` used
  to be reported on `arg0`. Now the inner object is its own key; pinned by
  `test_a_release_on_a_field_pointer_belongs_to_the_field_object`.
* **Two field objects merged.** `arg0+0x30` and `arg0+0x38` used to be one object ("the argument"),
  which turns two correct single drops into a fabricated double free. Pinned by
  `test_two_different_field_objects_are_not_a_double_release`.
* **Take counted as consumption.** A `+1` reference operation set `DROP_REF`. Fixed: a take is not
  a consumption.
* **Global object inheriting into the argument.** A drop of a pointer stored in a global is not a
  drop of the argument. Pinned by
  `test_a_release_through_a_global_pointer_belongs_to_the_global_object`.

On the real image the generic double-release detector produced **0** hits in 1'171 bodies. With the
container-merging defect still in place it would have produced a large number of fabricated double
frees; that was the false-positive risk worth eliminating before any finding is reported.

## Unknown alias relationships (declared, not guessed)

* **Scaled-index loads** `[table + index*8]`: the element is a class of objects, not an object. No
  key is produced. This is the single largest source of unattributed release sites.
* **Indirect calls** (`call reg` / `call [mem]`): the callee is unknown, so every argument is marked
  escaped and every return is unclassified. Bodies containing one are `partial`.
* **Interior pointers into field objects**: `lea reg, [loaded_ptr + k]` collapses two different
  offsets, so it is refused rather than attributed to the wrong field.
* **Field paths deeper than 2**: refused (`MAX_PATH`).
* **rsp-relative slots after an unbalanced stack adjustment**: the frame-slot map drops to unknown
  when two paths disagree about the stack pointer.

## Unresolved call boundaries

* 12 direct call edges out of the `aio_multi_wait` handler were resolved and summarised; none reports
  an ownership effect on its arguments, and that conclusion holds only as far as those bodies are
  `complete`.
* Recursion: 216 lookups hit the recursion guard during the coverage run; the call graph revisits a
  function within the depth cap and that is refused, not approximated.
* 0 of 370 chains in the proof ladder advanced above `CFG_REACHABLE`; `REQ_OBJECT_FLOW` remains open
  for all of them. The ownership dimension's new `REFUTED` verdicts (201) are not an advance of the
  ladder and do not clear any requirement.
