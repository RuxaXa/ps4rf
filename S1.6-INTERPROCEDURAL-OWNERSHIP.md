# S1.6 — Generic interprocedural ownership and lifetime summaries

Baseline: S1.5 = `5354aba4c18bdcec72b36e25c0a411c2ad4afcd0` (PARTIAL, accepted).
This document describes the S1.6 layer itself. Measurements are in `S1.6-MEASUREMENT.md`, the
limits in `S1.6-COVERAGE-AND-LIMITS.md`.

## What the layer is

`tools/discovery/summaries.py` answers, for one function and without any exploit knowledge:

* what the function does with each **object** it can see — read, write, compare, take a reference,
  drop a reference, free, pass on, store somewhere, return;
* what it returns — a constant, an alias of an object, a value loaded out of it, a callee result,
  or nothing it can decide;
* whether each of those is a **must** (every path) or a **may** (one path), and whether the body
  was walked completely enough to publish a *negative* statement at all.

Callee summaries are composed: a function that receives a pointer, hands it to a callee that drops
a reference and then returns, is summarised as consuming that reference. That composition is what
"interprocedural" means here.

## Design rules (each one is a defect this replaces)

1. **Object-keyed, not register-keyed.** A key is `(kind, origin, path)`: `arg0`, `arg0+0x30`,
   `glob0x1a5a120+0x18`. Registers only ever carry a key. A summary keyed by register name merges
   two generations of `r13` into one object, which is the recurring defect of the S1.4 layer.
2. **A container and the pointer inside it are different objects.** `arg0+0x30` has its own
   reference count and its own life cycle. Attributing the inner drop to `arg0` would be a false
   positive; throwing the inner object away (the previous behaviour) is why nothing was ever
   attributable on the kernel.
3. **Field paths are bounded (`MAX_PATH = 2`).** Further indirection becomes top, not a guess.
4. **Refusal instead of a clean bill.** Incomplete or budget-stopped bodies mark every negative
   claim `UNKNOWN`. `reads == []` is only published from a complete body, because "no read found"
   and "no read possible to find" are different statements.
5. **A `may` is never promoted to a `must`.** Block dominance alone is insufficient: a conditional
   branch can jump *past* an instruction into the middle of the same block, so the block is
   reached either way while the instruction is skipped. `_skipped_by_branch` closes exactly that
   hole, which is why a conditional `free` stays `MAY_RELEASED`.
6. **No synthetic hop status.** A hop is `PROVEN` / `CONDITIONAL` / `UNKNOWN` / `REFUTED`, never
   `possible`. The word "possible" belongs to entry attribution, and a synthetic `possible` hop
   substantiates a chain that nothing witnessed.
7. **An indirect call invalidates everything downstream.** Its target is unknown, so no argument
   can be claimed untouched and no return can be claimed to be anything.
8. **An escape is not a release.** Storing the pointer into a global or into another object's
   field keeps the object alive; the postcondition stays `LIVE`.

## Object model

| value | meaning | object key |
|---|---|---|
| `("obj", key)` | the register holds that object | `key` |
| `("ptr", key, off)` | interior pointer into the object | `key` (same object) |
| `("const", v)` | immediate | none |
| `("ret", site)` | result of a callee | none |

A load through a base register produces the object **stored at** base + displacement, i.e. one path
element deeper. Interior pointers keep their object and carry their displacement separately, so
`lea rax, [arg0+0x10]; mov ecx, [rax]` is a read of `arg0` at `+0x10`, not a new object.

Frame slots are tracked per block (`rbp`-relative, and `rsp`-relative in entry-`rsp`
coordinates), because a pointer normally survives a call by being spilled. A pointer kept in a
global is tracked as a global object, because that is what kernel code actually releases.

## Return classification

`ARG_ALIAS` (same object, no new reference), `FIELD_LOAD` (a *different* object — never an alias),
`CONST`, `NEW_OBJECT` (a callee result; ownership is **not** claimed), `UNKNOWN`.

## Soundness fixes made in S1.6

Both were found by fixtures, not by reading code:

1. **Guarded release reported as unguarded.** `lock xadd [obj+0x28], eax` leaves the *previous*
   count in `eax`, so `cmp eax, 1` is the count test. The guard prover only seeded the object
   register, so a correctly guarded release was reported `unknown`/unprotected — a false alarm in
   the dangerous direction. Fixed in `handles.guard_proof` (seed the `xadd` destination).
2. **Conditional release reported as unconditional.** A `je` over the release call into the same
   block satisfied block dominance. Fixed with `_skipped_by_branch`.

## Wiring into the proof dimensions (P1)

`chains.ownership_summary_dimension` consumes the summary and is evaluated on its own inputs.
`PROVEN` needs a `must` transfer out of a **complete** body with at least **two independent
witnesses** (the release/refcount site and the placement or field that shows which object it acts
on). A conditional release, an unguarded decrement or an indirect call cannot reach `PROVEN`.
Authorization and entry reachability are not inputs to this dimension: a missing gate or an
unresolved entry path must not suppress an ownership fact, and an ownership proof says nothing
about privilege.

## Hop rungs (call edge judgement)

`hop_at` composes the caller's object with the callee's effect. The placement question is answered
from the **forward value chain** (`caller_argument_objects`), not from a backward register window:
on this kernel the object normally arrives from a frame slot or a global, so a window over argument
registers finds nothing. The object that travels is then the caller's object *at the path the callee
reaches into*, e.g. caller `arg3` + callee path `+0x60` = `arg3+0x60`.

| status | condition |
|---|---|
| `PROVEN` | placement proved, callee consumes the reference with `must` strength, callee body complete |
| `CONDITIONAL` | placement proved, callee consumes the reference at a **concrete witnessed site**, but only on one path (or the callee body is incomplete) |
| `REFUTED` | placement proved and the callee body is complete but consumes nothing on that argument |
| `UNKNOWN` | placement not proved, no callee summary, or the callee's effect on that object is undecidable |

`CONDITIONAL` exists because on this kernel *every* consuming callee is path-gated: returning
`UNKNOWN` for a witnessed transfer would hide evidence, and returning `PROVEN` would claim all
paths. The rung is pinned by `test_a_path_conditional_consumption_is_conditional_not_unknown`.

## What the layer does **not** do

* It does not decide reachability, privilege or exploitability.
* It does not resolve indexed loads: `[table + rcx*8]` yields no object, because the element is a
  *class* of objects, not one object. Reporting a double release across such a class would be a
  fabricated finding.
* It does not prove a *global* claim such as "this kernel has an interprocedural ownership flow";
  that is a measurement question, answered in `S1.6-MEASUREMENT.md`, and the answer on FW 13.52 is
  currently zero.
