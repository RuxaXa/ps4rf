# S1.7 — Measurement: indexed identity on FW 13.52

Image: `kernel.bin`, SHA-256 `cf157ffdbae872a20bbb9a46c8518b53d96c1ed75d4e73878466a295d92eca35`,
`NOT_PRISTINE` (unchanged from S1.6). Release anchors `0x96e0`, `0xc28d0`.

## Two instruction-level witnesses (new in S1.7)

### A — `0xc56f0`, slot `tab[*(arg0)+0x0][arg1*8]`

```
0xc56fb  cmp  dword ptr [rdi + 0x28], esi   ; arg0->count vs arg1
0xc56fe  mov  rbx, rdi                       ; rbx = arg0
0xc5703  mov  rax, qword ptr [rbx]           ; table base = *(arg0)
0xc5706  mov  r14d, esi                      ; index = arg1
0xc5713  mov  rdi, qword ptr [rax + r14*8]   ; <-- slot load: the object
0xc5726  lock cmpxchg dword ptr [rdi + 0x28], ecx   ; take a reference
0xc5730  cmp  rdi, qword ptr [rax + r14*8]   ; still the current slot?
0xc573b  lock xadd dword ptr [rdi + 0x28], eax      ; drop the reference
0xc5740  cmp  eax, 1
0xc574e  call 0xc28d0                        ; <-- release, anchor
```

Table instance `*(arg0)`, index provenance `arg1`, scale 8, load `0xc5713`, release `0xc574e`,
ownership `DROP_REF`, strength `may` (path-gated by `cmp eax,1`).

### B — `0xc66f0`, slot `tab[*(arg1)+0x0][arg2*8]`

```
0xc6742  mov  rsi, qword ptr [rbx]           ; table base = *(arg1)
0xc6777  movsxd rax, r14d                    ; index = arg2 (sign-extended)
0xc677a  mov  r15, qword ptr [rsi + rax*8]   ; <-- displaced slot content = the object
0xc677e  mov  qword ptr [rsi + rax*8], rdx   ; reallocation: new generation
0xc67b4  lock xadd dword ptr [r15 + 0x28], eax
0xc67c2  mov  rdi, r15
0xc6883  mov  rsi, qword ptr [rbp - 0x38]
0xc6887  call 0xc28d0                        ; <-- release, anchor
```

This is a copy-and-swap: the released object is exactly the slot's *former* content, and the store
at `0xc677e` is why the generation has to be part of the identity.

Both witnesses are `may`, so both sit on the CONDITIONAL rung. **No PROVEN slot exists yet** — that
would require a must-strength consumption on every path.

## The 229 unattributed release sites are unchanged

The census at release-anchor call sites over the 354 finding functions is identical before and after
S1.7: **7 `arg`, 30 `ret`, 229 unresolved**. The two witnesses come from the wider closure, *not*
from those 229. Stated plainly: the frozen acceptance criterion asked for a witness "from the 229
previously unattributed sites", and that is **not** met.

Why: the base of the load, not the index, is what breaks there. 1'734 of 1'910 unresolved object
accesses are `load_untracked_base` — the pointer that would be the table is itself unknown. Index
identity was a real and measurable step, but it is not the binding constraint at those sites.

## Verdict

* Real indexed object identity on FW 13.52: **met** (two instruction-level witnesses).
* Witness from the 229 target sites: **not met** (base provenance, not index provenance, is the
  blocker).
* Negative controls of S1.6: **unchanged** (3 same-caller, 3 other-register, `SUPPORTED`).
* Regression: 260/260 discovery tests, 42/42 summary tests, fixture byte check green.
