| | S1.4 | S1.5 |

**All 23 are `CONDITIONAL`, none `PROVEN`, none `REFUTED`.** The typical evidence line is
`add rsi, qword ptr [rip + 0xd7c966]` reading the prison0 slot: the slot is *referenced*, but the
loaded pointer is neither dereferenced nor compared within the next 8 instructions, so it is not
shown to be a credential check. The strength rule is the reason the number is 0 and not 23 —
calling those 23 gates would have been the artificial upgrade this phase forbids.

Statuses: `{UNKNOWN: 687}`. The obligation text stays: no authorization symbol is resolved in
this firmware (`priv_check_cred`, `kauth_cred_issuser`, `suser`, `p_cansee`, `cr_cansee`), and the
`cdevsw` records carry no mode.

**Provenance note on the concurrency row.** `concurrency_dimension` was written after the
chains artefact existed, so those 370 verdicts were recomputed from the saved `scan.json` and the
saved chains artefact (`posthoc_concurrency.py`) with the same function the pipeline now calls —
no graph rebuild, same inputs. Every other row comes from the pipeline run itself.

## P4.5 — remaining blind spots

1. **Authorization is still the binding constraint.** 344 chains UNKNOWN, 26 CONDITIONAL, 0
   PROVEN: no chain can be shown to be reachable by an unprivileged caller.
2. **Ownership is 0/370.** Multi-hop ownership needs per-function argument/return summaries; the
   return half is explicitly UNKNOWN because a returned object is consumed in the caller.
3. **Concurrency is modelled, not proved.** 338 CONDITIONAL verdicts are lock-coverage facts
   (`uncovered_stores`), and the detector's own counter-evidence caps them: an unlocked store is
   not a shared-state store until the object is shown shared.
4. **`exploitability` is unreachable offline by construction**, so `EXPLOIT_CHAIN_VALIDATED`
   stays 0 no matter how good the analysis gets.
5. **Relapse**: PS4 13.52 applicability and the raw13g attribution are PROVEN by PSDevWiki;
   syscall 663 is locally PROVEN to be `aio_multi_wait → 0x11ff50`, and our top-ranked finding
   sits on that handler. The vulnerable instruction/lifetime transition and historical
   root-cause reproduction remain UNKNOWN: the public vulnerability entry says the bug
   description is still to be documented. See `S1.5-RELAPSE-CORRECTION.md` and
   `S1.5-INDEPENDENT-RELAPSE-REVIEW.md`.

## Two defects of my own that this run caught

1. `finding["entry"]` is a label *string*; `dimensions_for` read `.get("witness")` off it and
   **all 211 entry-rooted chains failed to compose** (`AttributeError: 'str' object has no
   attribute 'get'`). Fixed, regression test added. The first S1.5 run reported
   `{NOT-COMPOSED: 211}` because of it and was discarded.
2. `objectflow` refused every finding with a bare `{"proved": False, "why": …}` record; a caller
   reading `record["local"]` crashed. Every refusal now carries both halves, pinned by a test.

## Verdict for the phase

**PARTIAL.** Stated as three claims:

* **PASS** for P1 (six independent dimensions, no dimension suppresses another), P2 (100 %
  authorization coverage, honest strength rule, zero artificial upgrades), P3 (local and
  interprocedural separated, 0 ownership transfers rather than a guessed number), P4 (S1.4
  reproduced exactly, A1 counterexamples pinned green, Relapse firmware/build/dispatch mapping
  independently corrected and evidenced).
* **FAIL** for the goal of "first demonstrable semantic gain beyond CFG reachability": object
  identity is proved (40 chains) but cannot be *used*, because authorization stays UNKNOWN for
  every chain and ownership is 0/370. No chain advanced past `CFG_REACHABLE`.
* **BLOCKED** on external inputs, not on analysis: authorization symbols for 13.52 (or a
  `cdevsw` mode table), an image inside an affected range for any holdback family, and a
  family-level oracle to make a negative control decidable.
