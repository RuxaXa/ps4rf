# S1.7 — Indexed Object Identity

Baseline: S1.6 = `d8de635`, tag `s16-partial-baseline`, frozen as PARTIAL.
Hypothesis and acceptance test were frozen in `S1.7-HYPOTHESIS.md` before any run of this phase.

## What was built

**Slot identity.** A load through `[base + index*scale + disp]` no longer yields nothing. The slot
becomes an object in its own right:

```
key  = ("tab", (base_key, index_term, scale, disp, generation), path)
label= tab[<base>][<index term>*<scale>+<disp>]@g<table epoch>.<call epoch>
```

The entire tuple is the identity. Two accesses are the same object only if the table instance, the
index expression, the scale, the displacement and the generation all agree. "An element of table X"
is a class, and a class is never used as identity.

**Index provenance is a term, not a register.** The value of the index register is tracked through
`mov`, `movsxd`/`movsx`/`movzx`, `cdqe`/`cwde`, `lea`, `add`, `sub`, `and`, `or`, `xor`, `shl`/`sal`,
`shr`, `sar` and `imul`, with a depth bound of 4. Roots are `arg<i>` and constants. That is what the
kernel actually needs: `i & 0xff` is a bucket mask, `movsxd` + `shl` is array-of-struct addressing,
`lea rax,[rax+rax*2]` is a stride. A term that contains a load or a call is **not** stable — reading
it twice can yield two different values — and is refused.

**Generation.** A store through a table bumps that table's epoch, so a slot read after a
reallocation is a different object. A call that cannot be resolved bumps the global epoch, because
it may store into any table. Reallocation is therefore a first-class negative case, not a special
rule.

**Refusals are counted, not swallowed.** Every object access the walk cannot key is recorded with a
reason: `load_untracked_base`, `index_without_provenance`, `indexed_load_untracked_base`. Those
counters are what make the ownership verdict sound (see `S1.7-SOUNDNESS-REFUTED.md`).

## Identity rungs

| Claim | Condition |
| --- | --- |
| same slot | base key, index term, scale, disp and generation all structurally equal |
| different slot | any of them differs — different index, different input to the same mask, different stride, or a store in between |
| no claim (`UNKNOWN`) | index without stable provenance, or base not tracked |

A structurally different but semantically equal term (`2*i` vs `i+i`) is refused rather than
normalised. The refusal direction is the safe one.

## Fixtures

`tests/fixtures/discovery/summary-fixtures.S` gained six cases with explicit claims, assembled with
`as`/`ld`, byte-pinned by `gen_summaries.py --check`. `tests/test_discovery_summaries.py` is now
**42 tests** (was 32):

* `callee_index_drop` — a slot is an object with table+index identity and `FREE` ownership;
* `callee_index_double_drop` — same slot twice ⇒ double release;
* `callee_index_two_indices` — index `rcx` vs `rdx` ⇒ **no** claim;
* `callee_index_reallocated` — store into the slot between reads ⇒ **no** claim;
* `callee_index_unknown_index` — index reloaded from memory ⇒ **no** claim, no table key;
* `callee_index_constant`, `callee_index_masked`, `callee_index_struct_scaled` — positive;
* `callee_index_masked_other_input`, `callee_index_struct_other_stride` — negative;
* `test_a_body_with_unresolved_object_accesses_cannot_refute_ownership` — the soundness gate.

## Limits

* A slot whose base is not tracked is not identified: the base must reach the load through a tracked
  argument, global, frame slot or field. Base provenance is the dominant remaining gap, not the
  index (see the measurement).
* Slot identity is per function body. Two bodies reading the same slot are not correlated; the
  generation cannot be compared across a call boundary.
* `disp` is part of the identity at a fixed scale, so `[tab+idx*8+8]` is the next slot. Reading a
  *field of the pointed-to object* through the same expression is therefore described as a different
  slot, which is conservative but not exact for tables of large structs.
